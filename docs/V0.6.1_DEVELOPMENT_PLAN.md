# SC Profile Editor v0.6.1 - Development Plan

**Branch:** `v0.6.1-development`
**Status:** In Progress
**Release Type:** Patch (bug fixes + device templates + enhancements)

---

## Overview

v0.6.1 focuses on fixing critical bugs discovered in v0.6.0 testing, completing all remaining VKB device PDF templates, and minor UI/UX improvements.

---

## Critical Bug Fixes (GitHub Issues)

### Issue #9: Controller Detect Input Doesn't Work 🔴 CRITICAL
- **Reported:** November 29, 2025
- **Severity:** High - Breaks core "Detect Input" feature for VKB controllers
- **Description:** Keyboard detect input works, but VKB controllers (joystick) do not
- **Impact:** Users cannot auto-detect VKB button presses
- **Status:** To be investigated and fixed
- **Testing:** Must test with actual VKB controller connected

### Issue #8: Exporting XML Doesn't Change Profile Name 🔴 HIGH
- **Reported:** November 25, 2025
- **Severity:** High - Breaks profile export functionality
- **Description:** Profile name in XML export doesn't update when changed in the app
- **Impact:** Users cannot properly name profiles for Star Citizen import
- **Status:** To be investigated and fixed
- **Location:** Likely in `src/exporters/` or profile XML generation code

### Issue #7: Auto Precision Mode Toggle Mapping Fails 🟡 MEDIUM
- **Reported:** November 25, 2025
- **Severity:** Medium - Specific action mapping fails silently
- **Description:** Mapping "Auto Precision Mode Toggle" to VKB button shows success but doesn't display in Device View
- **Impact:** Specific action cannot be mapped (affects one action)
- **Status:** To be investigated - may be a label/display bug rather than mapping bug
- **Testing:** Test with VKB EVO base, button F1/27

## Development Workflow

### Phase 1: Bug Investigation & Fixes
1. Set up test environment with VKB controller (if available) for Issue #9
2. Investigate Issue #8 - locate profile name export code
3. Investigate Issue #7 - determine if label/display or actual mapping bug
4. Implement fixes and verify

### Phase 2: Device Templates
1. Locate existing device PDFs in `visual-scratch/` directory
2. Create PDF form field mappings for each new device
3. Add device entries to `template_registry.json`
4. Test Device View loading and interaction for each template
5. Verify button mapping and label display

### Phase 3: Testing & Release
1. Comprehensive testing of all fixes
2. Test all device templates in Device View
3. Update CHANGELOG.md
4. Increment version to 0.6.1
5. Create release notes
6. Build executable and installer
