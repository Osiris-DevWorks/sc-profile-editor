### 4. Control Table Not Updating After Remap
**Issue:** When editing an action from the Controls Table and remapping it, the table didn't update with the new input/device values

**Root Cause:** Two-part issue:
1. RemapDialog couldn't find unmapped actions (those with input codes ending in underscore)
2. `accept_changes()` method wasn't applying the new input code to bindings before emitting signal

**Solution:**

- When binding is provided (from table edit), use it directly instead of searching
- Modified `on_edit_input_clicked()` to pass binding object: `RemapDialog(..., binding=binding)`
- Updated `accept_changes()` to apply input code changes to bindings in single_action_mode

## Key Technical Notes

### RemapDialog Binding Fix
The binding parameter pattern allows RemapDialog to work in two modes:
1. **Search mode** (no binding provided): Searches profile by input code
2. **Direct mode** (binding provided): Uses binding directly
This solves the unmapped action detection problem where input codes ending with underscore couldn't be found.

### Dark Mode Colors
Using `palette(text)` instead of hardcoded colors is the Qt-recommended approach for theme-aware styling. Automatically respects:
- Windows light/dark mode setting
- macOS light/dark mode
- Linux theme settings

### Installer Registry Path
The installer writes directly to: `HKCU\Software\SC Tools\Star Citizen Profile Viewer\sc_profiles_directory`
This matches the exact location Qt's QSettings uses on Windows, so the app picks it up immediately on first run.
